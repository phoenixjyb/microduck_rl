# Dense friction append/prefix CPU component

## Why this separate component

The [zero-prefix dense-row fixture](2026-10-07-dense-friction-cpu-fixture.md) now has exact-source CPU reproduction on Mac and WSL, but does not test preservation of already populated constraint rows. In the frozen installed `constraint.py::make_constraint`, equality kernels precede the DOF-friction launch (the latter at lines2768–2790), so the shared `nefc` may already be nonzero. This source ordering does **not** establish what happened in the retained GPU simulation, nor show that the plant had equality rows at that boundary.

The new [prefix fixture](../../src/mjlab_microduck/stance_friction_prefix_cpu_fixture.py) tests only a synthetic, isolated dense CPU append operation: initial `nf=0`, per-world initial `nefc` between0 and capacity, finite opaque non-friction leading rows, bit-distinct poisoned suffixes and populated unused sparse scratch. It composes the same frozen original kernel with the same ascending-DOF candidate. No equality kernel, robot model, constraint pipeline, forward, solver, integration, sparse/tendon path, CUDA, graph, actor, storage, learner, recording, perception or physical device is executed. It is not a runtime replacement.

Protocol `microduck-dense-friction-prefix-cpu-fixture-oct7-v1` is separate; no old guard or negative is modified. The base fixture module must remain SHA256 `8e96c5077f248aad06cacab4c3a45f17cd6b3c35c09c7a46457281916e8046d9`, with its original kernel/helper/launch, frozen package tree and CPU platform guards unchanged. Borrowed input helpers and own control/capture helpers are pinned by object/code identity. Before/after source/module/helper identities are retained. All five cause/native/full-window/training/physical flags are permanently false, even when the component is exact.

## Actual arrays, append and preservation

Use plain bounded contiguous float32 NumPy inputs for1–4 worlds,20 DOFs, independently1-or-nworld model rows, and capacity1–32. Initial prefix counts are literal contiguous int32 vectors of length nworld within capacity. Revalidate the one caller-independent copied input/count snapshot. Only literal CPU allocations/launches are allowed with CUDA visibility empty and disable flags0/dense mode. Inputs and all output buffers for the original and two candidate calls are freshly allocated, kept alive and checked as63 distinct non-overlapping contiguous CPU allocation ranges. Actual input shapes, Warp dtypes/strides, devices, pointers and complete bits before/after must match the owned snapshot.

Original launches once over `(worlds,20)`; each fresh candidate launches once over worlds. Capture each complete after bank once, and use that same owned snapshot for both report and decisions. Retain all15 before/after banks for all three runs: `nf`, `nefc`, type, ID, dense J, pos, margin, D, vel, aref, frictionloss, row-nnz, row-address, column-index and `efc_nnz`. Float32 banks are transported as uint32 word carriers with explicit shapes; this preserves signed zero and NaN poison without treating inactive poison as active numerical data. The scratch buffers are deliberately populated opaque fixtures, not evidence of actual sparse execution.

For every world, positive friction-loss values independently determine proposals. Expected `nf` equals that count; expected `nefc` is prefix count plus proposals, even on overflow. Stored total rows are `min(nefc,capacity)`; appended friction rows start at the original prefix and stop at that limit. Validate literal type1, finite active fields, valid unique positive-input DOF addresses, and independently require a +1-at-DOF/+0-elsewhere dense Jacobian. Both candidate address sequences must equal the ascending visible expected DOFs. Compare complete original/candidate active fields by DOF, preserving multiplicity; do not require the original atomic row order to be ascending. Require the two complete candidate after banks to be byte-identical.

Leading prefix rows, unvisited suffix poison, all scratch banks and `efc_nnz` must remain bit-identical to their own initial snapshots in every run. **Any overflow is explicitly negative**, including a full prefix with zero visible new rows but positive complete proposal counts; an equal visible subset never qualifies the component. Component exactness additionally requires complete counts/addresses, preservation, ascending candidates, complete candidate replay and original/candidate addressed fields. It cannot qualify the old GPU repeat or authorize training.

## Later boundary, not admission

It should start with these synthetic literal inputs and fresh buffers; using real M6/robot data would be a separate scope and source/input identity gate. Compare one original against two fresh candidate launches, by address for original equivalence and complete bytes for candidate replay. If a compiled identity cannot be captured, report that gap instead of substituting source identity. No solver, runtime kernel interception or full simulation may be inferred from an exact isolated component.

Read-only inspection of frozen Warp1.12.0 `warp/_src/context.py` (408818 bytes / SHA256 `eb099d908c50effc3cacbf7ecc408be4187ca9a6a6f72e1e85c70676961524ee`) clarifies that boundary: `ModuleExec` at lines2273–2284 retains an opaque handle, source/options module hash, device and metadata—not a loaded-device-code digest. `_compile` at2713–2771 can reuse cached PTX/CUBIN files; `load` at2938–3042 resolves the binary path and loads it. A future separately implemented probe should bind the actual original and candidate artifact paths/formats, whole binary and metadata bytes, source/options/toolchain, device architecture and handles before/after each launch. PTX SHA identifies retained PTX only; these APIs do not expose the driver's JIT machine-code bytes. CPU object or source/module hashes must not be mislabeled as loaded CUDA binary identity. None of this read-only inspection loaded, compiled or launched CUDA.

An explicit `load(binary_path=..., output_arch=..., meta_path=...)` can avoid re-codegen at2985–2993, but an already cached matching `ModuleExec` returns **earlier** at2951–2956 and bypasses those supplied paths.
