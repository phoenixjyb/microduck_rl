## Smallest staged qualification, not a campaign

1. **Device preparation and no-update wiring.** Hash the immutable D1 parent
   before decode; restore its exact actor and critic without optimizer,
   simulator, storage, RNG or normalizer resume. Verify state hashes before
   and after transfer to the declared device, unique parameter ownership,
   real empty 64-world CUDA storage and empty Adam. No environment or update
   is required for a preparation check, and this is not throughput evidence.
2. **Actual fixed-row CUDA64 no-update rollout.** Bind the real scheduled
   runtime, compiled plant, row declaration and native policy/storage objects.
   Retain actual actor/critic inputs, unclipped stochastic actions/log-probs,
   controls, every accepted force phase, physical/clock boundaries, rewards,
   storage writes and private/caller random streams before independent replay.
   A complete 28-transition record answers short integration and observed
   resource/timing questions only. No real terminal means the terminal gate
   remains open; never inject clocks, resets or failures to close it.
3. **Deficit-gated one-update qualification.** Only after an unchanged-parent
   trainable deficit is retained and independently replicated should an actual
   CUDA64 rollout-to-update diagnostic be admitted. Persist and independently
   score its rollout before the update-attempt marker. Require exactly one
   declared update, all 20 optimizer step outcomes, finite gradients/parameters/
   Adam moments, correct storage clear, fresh-replay agreement and exact
   pre/post hashes. Finite loss is not evidence of improved recovery.
4. **Separate real terminal/storage/reset exercise.** A short horizon cannot
   borrow the CPU common-timeout ledger. A new protocol must reach a naturally
   observed terminal and retain its critic observation/target, timeout-only
   bootstrap exactly once, actual transition storage, done mask and pre/post
   reset state in the correct order. Common reset and untouched-sibling
   selective reset remain separate outcomes. If no genuine staggered terminal
   occurs, selective-reset qualification stays open.

This ordering is a design boundary, not a blanket launch permission. No deficit
in the gap screen means no evidence-driven reason to update these weights;
retain passing policies and limit further work to justified source/device
preparation or another separately declared capability gap. Any multi-update or
multi-seed campaign needs its own numerical/retention matrix and measured caps.

## Random streams and episode assignment are independent contracts

The CPU bridge saves/restores only CPU RNG state. A real CUDA learner must
declare which device performs Gaussian sampling and minibatch permutations,
retain the actual private CPU/CUDA stream states it uses, demonstrate their
advancement and preserve caller CPU/CUDA streams. A CPU seed or reported CUDA
flag cannot stand in for those native device operations. Actual CUDA optimizer
replay must use the matching CUDA math/profile; CPU replay is not a substitute.

The existing
[schedule declaration](../../src/mjlab_microduck/stance_recovery_schedule.py)
binds an ordered fixed row-to-cell map for the entire runtime lifetime. A fixed
64-row batch can qualify that map, not the lesson plan's 20% zero / 80% uniformly
sampled nonzero **per-attempt** curriculum. Per-attempt resampling needs a new
retained assignment/RNG/reset protocol; unsupported runtime reassignment must
not be presented as implemented behavior. Held-out cells never enter training
through an incidental row reassignment.

## Implemented preparation-only sibling

[CUDA64 preparation](../../src/mjlab_microduck/stance_recovery_cuda_policy_preparation.py)
is a separate callable at fixed 64 worlds, horizon 28 and learner seeds 653/659.
It authenticates the existing inherited lease before CUDA queries or allocations,
checks the real exact WSL source/host, requires only visible CUDA0 and pinned
RSL model/PPO/storage sources, hashes the immutable parent before CPU decode,
then strictly restores actor and critic before device transfer. State hashes
must match the D1 parent before and after transfer. Models remain trainable
float32, with positive actor scale and no gradients; the fresh stock PPO owns
the unique actor/critic parameter union in an empty Adam. Storage is actual
64-by-28 CUDA tensor storage, empty and finite, not a reported device flag.

Caller CPU and CUDA random streams are preserved. A fresh private CUDA generator
and its raw state are returned separately from the serializable receipt, with a
state hash, but neither is sampled, advanced or connected to PPO. This is not
sampler, transition, finite-update or training qualification. The callable has
no CLI, environment, rollout, optimizer-step, resume, export or admission path.
Stock PPO's inherited NaN-filling GAE is not qualified for future CUDA learning;
a later finite transition/update protocol must address it independently.
The returned raw caller CPU/CUDA snapshots and receipt hashes allow a later
retainer to check the measured before/after equality rather than borrowing a
boolean. They do not qualify CUDA action sampling or optimizer replay.

The supplied CPU-parent receipt must have the exact whole canonical hash,
parent/profile identity, strict actor/critic restoration and non-admitting
schema. That is input consistency, **not independent provenance**. The output
keeps `cpu_provenance_authentication_required=true` and
`native_cpu_provenance_authenticated_by_this_function=false`. Before native
use, a separately predeclared CUDA-hidden supervisor must authenticate the
retained historical/prerequisite evidence and fresh CPU loader result, bind
both to the exact source and launch, then start a distinct CUDA0 child with the
inherited lease. No late environment switch or loader bypass is permitted.

Owner-reviewed source tests also reject relabelled real CPU storage/parameters,
wrong visibility/profile/seed/world count, unbound receipt bytes, wrong parent
identity and every capability flag. All positive receipt fixtures are labelled
synthetic; no Mac test claims actual CUDA preparation. Native timing, resource
limits, output inventory, whole-file independent closeout and launch authority
still require a separate retained predeclaration before any new service starts.
